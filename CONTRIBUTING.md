# Contributing to SMMly

Thank you for your interest in SMMly.

## Where contributions belong

This repository contains organization-wide community health files and the public GitHub profile. Product application code, infrastructure, private operational details, and unreleased implementation work are maintained in private project repositories.

Public repositories may define their own contribution instructions. Follow the instructions in the repository you are contributing to.

## Before opening an issue or pull request

- Search existing issues and pull requests to avoid duplicates.
- Keep reports focused and include enough context to reproduce a problem.
- Never include passwords, API keys, access tokens, customer data, payment details, or other secrets.
- Do not publish security vulnerabilities in public issues.

## Pull requests

- Keep changes scoped and explain the reason for the change.
- Use clear commit and pull request titles.
- Update relevant documentation when behavior or instructions change.
- Be respectful during review and respond constructively to feedback.

Submitting a contribution does not grant permission to use SMMly trademarks or imply endorsement by SMMly.
